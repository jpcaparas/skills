# Gotchas and recovery

Use this reference when revision keeps producing motion without improvement.

## The edit changed the facts

Symptom: the prose is smoother, but a number, condition, causal claim, quotation, command, or degree of certainty moved.

Recovery:

1. restore the source version
2. rebuild the preservation ledger in `references/operating-contract.md`
3. make the smallest edit that solves the original language problem
4. run the fidelity gate before any further style pass

## The draft became clipped

Symptom: every sentence is short; the reader must reconstruct relationships.

Cause: clarity was confused with compression.

Recovery:

- reconnect clauses that share one thought
- restore cause, contrast, and sequence
- vary sentence length in response to information
- read `references/voice-and-rhythm.md`

## The draft became grander, not clearer

Symptom: ordinary claims now use prestige verbs, importance labels, or abstract nouns.

Cause: word replacement occurred without a clearer mechanism or fact.

Recovery:

- restore plain source wording
- name actor, action, evidence, and consequence
- read `references/genericity-and-stiffness.md`

## The humanisation pass became detector chasing

Symptom: good words and punctuation disappear; odd errors or slang appear; the writer no longer recognises the piece.

Cause: signals were treated as proof and statistical irregularity was mistaken for humanity.

Recovery:

- reject changes that do not improve ordinary editorial quality
- restore dialect, exact terms, quotations, and deliberate rhetoric
- treat scanner output as revision prompts only
- read `references/ai-isms-and-humanisation.md`

## The banned phrase came back in disguise

Symptom: `bridge the gap` becomes `close the divide`, `significant shift` becomes `major transformation`, or one prestige word replaces another.

Cause: the edit targeted spelling instead of the proposition.

Recovery:

1. restore the source meaning
2. identify the actor, action, old state, new state, mechanism, evidence, and consequence the source actually supplies
3. rebuild the sentence from those elements
4. delete, narrow, or query the claim when the source supplies no substance
5. read `references/formulaic-language-catalogue.md`

## A literal or technical use was removed

Symptom: the edit corrupts a phase shift, Shift key, pay gap, band gap, statistical robustness, quotation, identifier, or official term.

Cause: a contextual avoidance rule was applied as a raw string replacement.

Recovery:

- restore the exact term or literal byte-for-byte
- limit the edit to surrounding rhetorical prose
- record the deliberate exception in the preservation ledger
- test the phrase's function, not its spelling

## The edit invented experience

Symptom: first-person anecdotes, emotions, customer reactions, or scene details appear without a source.

Cause: ownership was added instead of recovered.

Recovery:

- remove the invention
- ask the writer for a real example when it is material
- keep the sentence impersonal or appropriately attributed until then

## The review rewrote without permission

Symptom: the user asked for diagnosis but received a replacement draft.

Cause: review and rewrite were not separated.

Recovery:

- restore the source artefact
- rank findings by reader impact
- cite exact passages
- label any rewritten line as an example

## The style request became imitation

Symptom: recognisable catchphrases, syntax, or persona from a named writer dominate the draft.

Cause: surface tics were copied instead of broad traits.

Recovery:

- translate the request into directness, evidence density, pace, formality, and narrative distance
- remove signature language
- rebuild from the writer's samples in `templates/personal-style-sheet.md`

## The page has the wrong shape

Symptom: sentences improve, yet the artefact remains hard to use.

Cause: a memo was treated like an essay, a guide like an explainer, or a reference page like a tutorial.

Recovery:

- stop line editing
- choose the reader task in `references/genre-modes.md`
- rebuild the opening, unit of composition, and ending

## The conclusion keeps summarising

Symptom: the ending repeats headings or restores generic optimism.

Cause: the writer did not choose a closing job.

Recovery:

- for a guide, verify success
- for a memo, decide or recommend
- for a report, state the supported implication or limit
- for an essay, turn outward
- for copy, make the next action clear
- cut the conclusion if the piece is already complete

## Formatting replaced thinking

Symptom: more headings, bold labels, and bullets made the page easier to scan but harder to understand.

Cause: visual hierarchy was used instead of argument, sequence, or comparison.

Recovery:

- return developing thought to paragraphs
- keep lists for genuine peers or steps
- rename headings to reader promises or claims

## The draft sounds warmer but less trustworthy

Symptom: enthusiasm, jokes, reassurance, or rhetorical questions soften a serious constraint.

Cause: warmth was added as performance.

Recovery:

- state the problem and consequence plainly
- help the reader recover
- let warmth come from attention and useful action

## A phrase match is a legitimate use

Symptom: a scanner flags a quotation, product name, technical term, legal phrase, or deliberate rhetorical line.

Recovery:

- retain it
- record the exception when the workflow tracks decisions
- test the surrounding paragraph rather than forcing a local substitution
- add a counterexample to the corpus if the same false positive can recur

## The author uses English differently from the editor

Symptom: revision standardises dialect, second-language features, or culturally meaningful phrasing that readers could already understand.

Cause: statistical familiarity was mistaken for clarity.

Recovery:

- restore identity-bearing choices
- edit only genuine ambiguity or requested house style
- explain optional standardisation rather than silently imposing it

## The opening carries the whole draft's anxiety

Symptom: the first paragraph defines every term, caveat, source, and conclusion.

Recovery:

- write the smallest honest opening that establishes the genre contract
- move evidence and limits to the point where the reader needs them
- keep one live reason to continue

## Every pass finds something new

Symptom: changes continue after the quality gates pass.

Cause: the work has no stop condition, or each pass creates defects for the next.

Recovery:

1. return to the last version that passed all applicable gates
2. name the remaining defect
3. if no reader-impacting defect can be named, stop
4. save alternatives as taste choices rather than overwriting the strong version

## Recovery principle

Restore first, then make the smallest corrective pass. Do not repair a damaged edit by adding another style layer on top of it.
